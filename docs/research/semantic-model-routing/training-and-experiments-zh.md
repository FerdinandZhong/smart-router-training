# Ossie 语义检索：实验、训练与模型选择

日期：2026-10-09。状态：研究方案，尚未实施本任务的训练或评测。

2026-10-10 更新：执行安排以[无图、低延迟研究计划](research-plan-zh.md)为准。
本说明保留模型接口与训练证据；图评分器不再属于本阶段训练任务。
主线优先微调 embedding，候选重排按质量与延迟收益决定是否保留。

## 研究判断

GLiNER2.5-Decide 和 Laya 仍有研究价值，主要承担召回后的候选重排。
第一阶段使用可建立向量索引的 embedding 模型。
可选第二阶段比较通用重排器、GLiNER2.5-Decide 和 Laya。
第三阶段补齐语义依赖，并检查所选上下文的完整性和一致性。
在线采用固定模板装配准确定义；LLM 摘要不属于当前快路径。
GLiNER2.5-Decide 和 Laya 的本阶段职责是评分与选择。

我们要验证的是：小型模型是否能提高固定预算内的完整语义上下文检索质量。
模型品牌、Ossie 格式和图扩展本身都不构成研究贡献。
应先明确现有方法的失败，再决定需要训练哪个模块。

本文整理并细化已有[实验计划](experiment-plan.md)，保留[文献综述](focused-literature-review.md)的证据边界。
新增核验覆盖官方模型卡、固定版本源码、GLiNER2 论文、GLiClass 和 LAVOIR。
本地与上游源码版本记录在[模型证据清单](model-evidence.json)。

## 术语统一

| 统一名称 | 本文含义 | 需要避免的混用 |
| --- | --- | --- |
| GLiNER2.5-Decide | 本项目已固定版本的分类模型 | 不将整个 GLiNER2.5 家族都称为相同架构 |
| Laya | 本项目固定的英文根模型及其 typed decision 结构 | 不将其与自动选择多个 checkpoint 的 Laya Router 混为一谈 |
| 候选召回 | 从完整目录找出待评估的语义对象 | 不等同于最终上下文选择 |
| 候选重排 | 根据问题重新评分有限候选集 | 不等同于离线 embedding 索引 |
| 完整语义上下文 | 足以支持已明确业务意图的定义及依赖集合 | 不等同于若干相关表，也不要求与唯一 SQL 的表集合完全一致 |

## 一、模型放在哪里

```text
已批准的 Ossie 文档 + 目录元数据
                  |
        多层描述符 + 声明依赖清单 + 索引
                  |
用户问题 -> keyword + embedding 候选召回
                  |
        可选重排器 / GLiNER2.5-Decide / Laya
                  |
       依赖补全 + 一致性检查 + 预算约束
                  |
       精确定义 + 可选局部摘要 / 请求澄清
                  |
           固定的 SQL 生成与验证流程
```

主实验首先保留三种粒度：模型、数据集、指标或字段定义。
每个描述符保留业务含义、适用条件和来源引用。
公式、必要过滤条件、粒度和时间规则必须来自已批准定义。
数据中未明确的信息保持未知，不通过模型生成补成事实。
装配最终上下文时，必须解析引用并计入真实文本的 token 数。

Ossie core 当前不定义跨模型引用或 bundle 格式。
目录关联和检索标识需要单独管理，并固定规范版本。
同名字段不自动构成可执行连接。[Ossie 官方规范](https://github.com/apache/ossie/blob/main/core-spec/spec.md)。

| 模型类型 | 优先承担的任务 | 本阶段的边界 |
| --- | --- | --- |
| 双编码器 embedding | 编码问题与描述符，建立大目录索引 | 用专门的检索目标训练，测量首阶段漏召回 |
| 通用 cross-encoder 重排器 | 联合读取问题和一个候选，预测相关性 | 必须纳入同数据训练的强对照 |
| GLiNER2.5-Decide | 判断候选是否符合问题；后续试验小候选组的多标签选择 | 每个候选仍需完整描述；不能把整个目录直接作为标签输入 |
| Laya | 判断候选是否符合问题；后续比较有条件的明确决策 | 首轮采用独立二元判断，不强制在所有候选中只选一个 |

GLiNER2 的正式论文支持 schema 驱动的抽取与分类结构。
它不是 GLiNER2.5-Decide 在 Ossie 检索上的效果证明。[EMNLP 2025 论文](https://aclanthology.org/2025.emnlp-demos.10/)。
Decide 官方模型卡支持运行时标签和标签描述。
本项目固定配置实际使用 DeBERTa-v3-large 与 `span` 架构。
这与 GLiNER2.5 家族中的其他架构需要区分。[固定模型卡](https://huggingface.co/fastino/GLiNER2.5-Decide/blob/5a7adf72a23b4d311abae6ce050d7f0012bb3416/README.md)、[固定配置](https://huggingface.co/fastino/GLiNER2.5-Decide/blob/5a7adf72a23b4d311abae6ce050d7f0012bb3416/config.json)。

Laya 根据问题中的选项位置生成分数。
官方模型卡提示了短选项预算、二元标签偏置和概率校准问题。
其动态选项接口允许描述新候选，但不保证对新业务定义的准确率。[固定模型卡](https://huggingface.co/convaiinnovations/laya/blob/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851/README.md)。

两者的当前评分路径都联合处理输入与候选信息。
我们尚未验证可用于独立目录索引的向量接口。
因此，将它们用于有限候选集更符合当前证据。
双编码器、候选联合编码和分组标签编码应分别计时。
一次 API 调用或一次批量 forward，不代表候选数增加后计算量不变。

## 二、已有训练能复用什么

本次只读取了原始 checkout，没有改变现有训练实现。

| 本地核验结果 | 对本研究的影响 |
| --- | --- |
| Laya 适配器冻结 encoder 和 act head，训练其余输出模块 | 旧结果是特定适配器结果，不代表端到端微调能力 |
| GLiNER 适配器只训练 `classifier.*`，编码器运行于 `no_grad` | 需要增加允许编码器更新的实验条件 |
| 两个适配器都围绕原路由任务创建训练行 | 需要新的问题—候选数据投影和标签 |
| 两个适配器都使用首尾保留策略处理超长输入 | 语义任务必须检查关键规则是否被截断 |
| 当前两个 10-epoch 配置都设为 2,048 token | 不能将 Laya 模型卡的默认 512 token 当作旧实验实际配置 |
| Laya 固定源码将单个选项文本限制为最多 48 token，并另有限制指令的预算 | 不能把完整业务定义塞进选项描述 |

Laya 的业务定义应放入候选正文。
指令和“符合／不符合”选项保持简短。
GLiNER 的首轮试验也使用完整问题—候选正文，以便公平比较。
两种 tokenizer 的 token 数不同，公平性首先要求保留相同证据。
较长输入能力另设实验，不能通过静默截断维持名义上的相同长度。

原有 1,300 条路由样本的成功标签不能直接成为语义检索标签。
可以复用训练基础设施、观测掩码、分组切分、checkpoint 和 TensorBoard。
主实验从各模型原始 checkpoint 开始。
旧路由微调权重只作为可选迁移对照，避免把负迁移误认为结构缺陷。

## 三、先准备什么数据

第一步保留已有的 240 个独立问题 episode 试点方案。
它用于检查标注规则、输入长度、候选覆盖率和失败类型。
正式训练数据再扩展到约 1,000–2,000 个审核后的 episode。
这些数量是规划值，不代表足以支持所有泛化结论。
同一问题展开出的候选对，不能算作独立业务问题。

| 数据组成 | 必须记录的内容 |
| --- | --- |
| 问题 | 原始表达、已确认历史、业务域、语言、episode 和模板分组 |
| 目录快照 | 表与模型的可见时间、版本、批准状态、来源哈希 |
| 合法答案 | 必要定义、依赖路径、允许的替代上下文集合 |
| 歧义 | 合法解释分支、需要澄清的槽位、确认后的解释 |
| 候选标签 | 符合已确认意图、不符合、尚未审核；与标签依据分开存储 |
| 结果证据 | 审核 SQL、独立参考计算和边界数据；仅用于监督与评估 |

从真实问题和已审核 SQL 开始。
SQL 解析提供表与字段的弱监督，专家补充业务定义与合法替代方案。
可借鉴 BenchPress 的 SQL-to-question 草稿审核流程，但合成问题单独标记。[BenchPress](https://www.vldb.org/cidrdb/papers/2026/p16-wenz.pdf)。

训练集应包含真实检索产生的困难负样本。
优先选择主题相似、业务口径不同的对象，例如净额与毛额、入账日与结算日。
未审核对象保持未知，不能全部当作负样本。
同一指标的不同合法实现也不能互相当作负样本。
对比学习的 batch 内负样本同样需要屏蔽这些情况。

自然问题、合成问题和压力测试分别报告。
错别字与同义改写保持原意；真正的歧义允许多个解释。
不要为了制造困难而强制给歧义问题标一个唯一表集合。
SQUAB 可帮助设计歧义与不可回答类型。[SQUAB](https://aclanthology.org/2025.emnlp-main.906/)。

## 四、必须完成的实验

| 阶段 | 对照与操作 | 回答的问题 | 是否训练 |
| --- | --- | --- | --- |
| E0：数据与上限 | 专家提供的完整上下文、当前上下文、检索上下文；固定下游生成器 | 问题来自目录缺失、检索遗漏，还是下游生成？ | 否 |
| E1：候选召回 | BM25、dense、调优后的 hybrid；K=20/50/100 | 强检索能否覆盖必要定义？ | 先不训练，再微调一个 embedding |
| E2：候选重排 | 同一候选池下比较通用重排器、GLiNER2.5-Decide、Laya | 决策型预训练是否提供增益？ | 三类模型使用同一监督池 |
| E3：依赖与组合 | 无补齐、声明依赖补齐、表级与类型化描述、注明改编的 REaR 对照 | 增益来自语义描述、装配，还是学习？ | 装配本身不训练 |
| E4：输入与预算 | 表描述与完整语义描述；2K/4K/8K 上下文；结构化上下文与局部摘要 | 业务定义能否在预算内保留？ | 优先复用已训练模型 |
| E5：泛化与规模 | 新领域、目录新增表、中英及混合表达、约 100/1,000/10,000 表 | 方法能否适应实际目录变化？ | 新表主条件冻结权重 |

以上数值均为起始规划值，先由试点检查可行性。
E1 的 K 是候选数量；E4 的预算是最终语义上下文 token 数。
二者不能互相替代。

E2 的主候选池由同一个冻结召回器生成。
训练时可保留召回遗漏的正例，但记录这种补入。
验证与测试不能补入 gold 候选。
可以另报 oracle 候选池的诊断结果，但不能计入真实系统结果。

先固定依赖扩展比较重排器，再固定重排器比较扩展策略。
随后组合最有希望的组件进行端到端评估。
不需要一开始训练所有因素的笛卡尔积。

REaR 已覆盖召回、扩展与精筛流程。
JoinGR 已训练问题条件下的图遍历评分器。
CORE-T 已评估没有数据库 ID 的混合目录选择。
这些文献限制了创新性表述。无图主方案优先比较强 hybrid、训练后的 embedding 和注明改编的 REaR。
JoinGR 与 CORE-T 保留为相关工作及后续可选对照，不要求首轮复现全部方法。
[REaR](https://aclanthology.org/2026.acl-long.1826/)、[JoinGR](https://arxiv.org/abs/2610.01064)、[CORE-T](https://arxiv.org/abs/2601.13111)。

## 五、具体训练安排

| 训练对象 | 输入与目标 | 初始训练方式 | 关键对照 |
| --- | --- | --- | --- |
| 双编码器 | 问题与语义描述符；多个审核正例和困难负例 | 标准多正例对比学习 | 原始 embedding；同描述符的 hybrid |
| 通用重排器 | 问题＋一个候选；是否属于合法上下文 | 标准 BCE，或常规 pairwise ranking | 原始重排器与同数据微调 |
| GLiNER2.5-Decide | 同一问题—候选正文；固定分类问题 | masked BCE；独立候选分数 | 原始、冻结编码器、编码器适配 |
| Laya | 同一问题—候选正文；简短二元判断 | 两个选项的 logit 差对应 masked BCE | 原始、冻结编码器、编码器适配 |

语义 embedding 的训练可参考 corpus-adaptive schema retrieval。
该工作使用目标目录合成问题和困难负样本，但它的主协议预先限定数据库。
我们的全目录与时间切分协议需要单独实现。[论文方法](https://arxiv.org/html/2607.13311)。

1. 先运行原始模型，确认输入、标签和评分接口正确。
2. 冻结编码器训练输出模块，建立成本较低的下限。
3. 为三个重排器提供相同调参预算，并执行允许编码器更新的条件。
4. 优先采用小学习率端到端微调；资源不足时，统一使用经过核验的参数高效适配方案。
5. 如果采用 LoRA，记录注入模块、rank、可训练参数和实际梯度，不能只记录名称。
6. 使用验证集选 checkpoint，再用独立校准集确定阈值。
7. 对入选配置运行三个种子，最后一次性评估锁定测试集。

起始超参数可采用 encoder 学习率 `1e-5` 或 `3e-5`。
输出模块可比较 `1e-4` 与 `3e-4`。
先限制每个骨干最多四个开发集配置，避免调参预算偏向某个模型。
建议上限 20 epochs，并在验证指标连续三次不改善后停止。
这些设置需要数据长度和梯度检查后确认，不是已经验证的最佳参数。

embedding 以候选完整覆盖率选择 checkpoint。
重排器以固定候选池、固定装配规则下的完整上下文准确率选择 checkpoint。
训练日志同时记录损失、优化步数、独立问题数和候选对数。
学习率、batch、warmup 与停止规则在最终测试前固定。
不以“训练满十轮”或训练损失持续下降作为效果结论。

两类模型的“只训练头部”并不代表相同训练容量。
Laya 的输出部分包含 Transformer 层，GLiNER 当前适配器训练 classifier。
必须报告实际可训练参数、训练时间和推理时间。
只有输出模块的试验失败，不足以淘汰整个骨干结构。

如果决策模型超过通用重排器，再增加配套骨干对照。
比较普通 ModernBERT/DeBERTa 配相同任务头的模型，以区分骨干、输出结构和决策预训练的影响。
GLiClass 也讨论了文本与运行时标签的联合编码，可作为后续同类结构参考。
其接口思想不等于已验证的 Ossie 检索优势。[GLiClass，2025 预印本](https://arxiv.org/abs/2508.07662)。

## 六、GLiNER 与 Laya 的专门检查

| 检查 | 试验设计 | 不通过时如何处理 |
| --- | --- | --- |
| 关键语义可见性 | 将否定、过滤条件放在描述的前、中、后位置，记录实际 token | 修复描述符与分块；不能继续使用不完整输入训练 |
| 标签措辞偏置 | Laya 比较 `noul` 与中性选项的二元 `choice`；两者均检查标签顺序 | 选择开发集稳定的编码方式，并保留敏感性结果 |
| 多候选干扰 | 对 GLiNER 的可选候选组改变顺序、组大小及干扰候选 | 主比较回到独立候选评分；分组结果单独报告 |
| 概率稳定性 | 在自然候选分布上校准，再测试 K 和目录变化 | 不把困难负样本训练下的原始分数直接解释成部署概率 |
| 语言能力 | 英文、中文和中英混合分别评估 | 多语言 checkpoint 作为独立实验臂，不能静默替换 |
| encoder 更新 | 确认梯度非零、权重变化、保存与重载一致 | 修复适配器，再判断微调是否有效 |

GLiNER2.5-Decide 和当前 Laya 根模型都以英文为主要适用范围。
公司问题的语言分布必须进入实验设计。
不根据用户使用中文讨论研究，就假定所有业务问题都是中文。

澄清决策放在第二阶段研究。
先区分业务歧义、定义缺失和预算不足，避免统一标成低置信度。
LAVOIR 已在 Laya 类结构上预测何时、询问哪个缺失信息。
它说明该结构有扩展空间，也限制了“会主动澄清”这一新颖性主张。
本研究暂不采用其价值信息目标或另造 cost-aware loss。[LAVOIR，2026 预印本](https://arxiv.org/abs/2609.30706)。

## 七、评价标准与继续条件

主指标为：**固定预算下的完整上下文准确率**。
对意图已明确、目录可回答的问题，选出的上下文应包含至少一个审核通过的充分集合。
还必须包含必要依赖，且没有引入冲突定义。
兼容但多余的内容影响精确率与成本，不自动使答案错误。
歧义、不可回答和预算不够的样本分别报告，不能通过拒答隐藏失败。

| 维度 | 指标 |
| --- | --- |
| 首阶段 | 必要定义 Recall@K；完整候选集合覆盖率 |
| 最终上下文 | 完整上下文准确率、定义精确率、冲突率、遗漏类型 |
| 业务结果 | 固定生成器下的业务正确率；SQL 执行成功率另报 |
| 泛化 | 新表必需问题的正确率、旧问题退化、领域与语言分组结果 |
| 效率 | 上下文 token、warm/cold p50/p95 延迟、吞吐、索引更新时间 |
| 训练 | 独立问题数量、优化步数、可训练参数、GPU 时间 |

不要用大量无关候选上的普通 accuracy 作为主要指标。
问题级结果应配合按 episode 或独立业务族重采样的区间。
三次训练种子与数据重采样反映不同不确定性，需要分别报告。

时间实验在 C0 训练，在 C1/C2 只增加索引对象并冻结权重。
新表及其依赖出现前，不能使用相关合成训练问题或未来日志。
新表与旧表混合的多表问题必须单独统计。
没有真实历史快照时，新增过程标为模拟。

GLiNER 或 Laya 的保留条件有两种。
其一，在相同预算下稳定提高完整上下文准确率。
其二，在质量相近时降低延迟、训练数据需求或 serving 成本。
实际改进阈值应由试点的方差与部署需求确定，并在最终测试前登记。

如果标准重排器效果相同或更好，则保留更简单的方案。
如果图补全解释了主要收益，则将贡献归于结构选择。
如果所有方法都被缺失业务定义限制，则优先修复数据。
这些结果都能形成可信的基准研究，不需要强行让既有模型成为最终方案。

## 八、执行优先级与待确认输入

1. 固定 Ossie 表达、目录快照和完整上下文标注规则。
2. 完成 240 个独立 episode 试点与 E0/E1。
3. 建立共同候选池，训练一个 embedding 和三类候选重排器。
4. 对入选模型执行图扩展、预算和新表实验。
5. 根据失败类型决定是否研究集合评分与主动澄清。

需要从实际数据中确认：问题与 SQL 的配对程度、关系图来源、目录历史快照和问题语言分布。
缺少这些信息不妨碍设计试点，但会限制后续泛化结论。
